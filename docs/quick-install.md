# LWAI Quick Install

## Copy this one line

`Set up Last War optimization using the instructions at https://lastwarai.com`

Paste it into a fresh AI conversation. For best results, use a higher reasoning/thinking setting when the host offers one.

`https://lastwarai.com` is the permanent first-party public installer/configuration endpoint. For a fresh install it resolves live GitHub Production server-side, retrieves the complete sanitized LWAI configuration from that exact immutable commit, and returns it in the same response.

The previously circulated `https://tinyurl.com/2yxf7f5x` is legacy compatibility only. Do not use it for new sharing and never treat a shortener response as Production authority.

## What happens

1. The AI retrieves LastWarAI.com.
2. LastWarAI.com has already resolved the live GitHub `main` SHA and returned the complete sanitized configuration associated with that exact commit.
3. LWAI looks for supported existing account/workspace state before treating the player as new.
4. A genuine new user chooses this-chat-only or cloud persistence with one compact yes/no question.
5. If cloud is chosen, LWAI lists only genuinely supported providers and requires an explicit provider choice.
6. Immediately before provider authorization, LWAI gives one compact workspace-only/no-password reassurance, then verifies its isolated workspace after connection.
7. Setup continues automatically through identity, strategic baseline and first useful evidence.
8. Later Production updates preserve LOCAL STATE and use live GitHub Production/exact-commit verification.

The user does not need to retrieve GitHub JSON, locate a commit SHA, follow a second engine URL, or paste the complete engine manually.

## Trust model

GitHub `main` remains the underlying sanitized Production source and current-version authority. LastWarAI.com identifies the resolved commit and explicitly permits independent source/provenance verification.

Search results, redirects, cached READMEs, mutable raw `main`, shorteners and model memory cannot determine the current version. Direct/modular runtime update transactions pin all trusted reads to one exact GitHub commit.

## Staying current

`release.resolver` resolves live GitHub `main`; `release.updater` pins each candidate update transaction to one exact commit and adopts only validated Production. Existing deployments keep last-known-good ENGINE and LOCAL STATE if current Production cannot be resolved safely.

`refresh engine` remains the permanent manual break-glass command and uses the same resolver transaction.

## Cloud security boundary

LWAI's internal storage rule is absolute: it operates only inside its dedicated Last War/LWAI workspace and unrelated connected-storage content is out of scope. The first yes/no persistence choice stays simple. After the user explicitly selects a provider, LWAI summarizes the boundary in plain language before authorization:

`LWAI will use only its dedicated Last War/LWAI workspace; everything else in your connected storage is off-limits. Connect through the provider/ChatGPT UI, and never paste passwords or login codes here.`

For Google Drive, choose `Allow always` only when ChatGPT actually offers it.

## Recovery
