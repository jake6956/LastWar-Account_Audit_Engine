PURPOSE
Stage-1 orchestration only. Resolve one live Production commit, pin the entire engine snapshot to that immutable commit, load mandatory modules, then hand off. No account/domain/provider playbooks belong here.

LIVE REF / CACHE SAFETY
Input from the public Stage-0 installer should include RESOLVED_PRODUCTION_COMMIT, the 40-hex SHA returned by the live GitHub `main` branch endpoint.
If absent, resolve live `main` using a GitHub-native connector/API when available, otherwise direct GitHub API branch retrieval, otherwise `git ls-remote` when genuinely available. Never use web-search results, indexed repository pages, cached `raw .../main/...` content, URL shorteners, or README snapshots to decide current Production.
If a fresh install cannot obtain a live 40-hex main SHA, stop rather than guessing. Existing deployments retain last-known-good ENGINE and LOCAL STATE.

PINNED SNAPSHOT
Let C = RESOLVED_PRODUCTION_COMMIT. Retrieve `releases/LATEST.json`, `engine/MANIFEST.json`, `releases/MIGRATIONS.json`, this loader, required modules, and fallback only from repository revision C. All mutable-path reads become commit-pinned reads before trust decisions.
Require LATEST/MANIFEST agreement on engine_version, engine_api_version, schema_version, Production channel, sanitized=true, account_state_included=false. Reject RC/Prod-Dev. Never mix files from different commits.

MODULE HANDOFF
Validate MANIFEST DAG/API/schema ranges. When Git blob identity is reproducible, verify each loaded module digest; otherwise require exact commit C plus module_id/module_version and do not claim unavailable hash verification.
Load mandatory core in dependency order, including `release.resolver`, `release.updater`, `release.bootstrap`, core operating/persistence/accounts/guidance. Load adapters/domains only when required. `release.bootstrap` owns startup/discovery handoff; `core.guidance` and `adapters.storage` own onboarding/provider UX.

STATE / MIGRATION
GitHub contains sanitized ENGINE only. Preserve LOCAL STATE. Supported older workspaces enter migration-capable core only and follow pinned `releases/MIGRATIONS.json`; domain modules wait for current schema. Unsupported paths fail closed. Never repair engine/retrieval uncertainty by rewriting private state.

UPDATES
`release.resolver` owns live-main resolution. `release.updater` uses that resolver at startup/reload/schema-sensitive boundaries and after the six-hour consequential-work TTL, then reads the candidate only at the resolved immutable SHA. Never compare/update from search-index or mutable cached `main` bodies.
`refresh engine` permanently forces the same resolver/update transaction while preserving LOCAL STATE. `check for LWAI updates` is an alias.

FAILURE
Fresh install: unresolved live ref or invalid pinned snapshot -> stop with the smallest actionable explanation; do not silently load a cached older release.
Existing install: keep last-known-good compatible ENGINE/LOCAL STATE. If C resolves but modular loading fails, use `engine/BOOTSTRAP_FULL.txt` from the same C; manual full-bootstrap transfer is final fallback.
