RECOVERY-FIRST STARTUP
When persistent state supports it, inspect unresolved Runtime Checkpoints and recent Runtime Journal entries after Workspace Registry/active_account_id resolution and before ordinary workflow continuation. Runtime Checkpoints are compact operational state; Runtime Journal is append-only write-ahead/event history. They are private local state, not public account data and not a transcript dump.

For each OPEN, WAITING_USER or RECOVERY_REQUIRED checkpoint relevant to the workspace or active account: read checkpoint/journal; inspect actual affected durable artifacts; treat verified durable state as authoritative; identify actions that truly committed; never replay verified successful writes; resume at the first unverified/pending action; advance safe point only after verification; mark COMMITTED only after intended durable end state is verified. Account-scoped checkpoints cannot silently resume under another active_account_id.

WAITING_USER/`done` survives reload. Context loss is not implicit batch completion. Never persist hidden chain-of-thought/full transcripts or duplicate screenshot/evidence blobs in checkpoints; store only objective, safe point, verified writes, pending input/work, material assumptions and concise resume instructions.
