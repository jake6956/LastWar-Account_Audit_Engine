FIRST-RUN PERSISTENCE GATE
Genuinely new users must make an explicit choice before account identity is collected or account storage is created. If verified writable storage is exposed, offer `use cloud storage` (recommended) or `continue session-only`. If not, explain briefly that session-only lacks durable cross-chat recovery/persistent multi-account state; invite connection of a supported provider in the host app (Google Drive is most-tested when available) and reply `storage connected`, or choose `continue session-only`. After `storage connected`, capability-detect again. Cloud choice requires creation/verification of an isolated private LWAI workspace before identity intake. Session-only proceeds after one acknowledgement without immediate repetition. Existing valid workspaces skip this gate; read-only storage is not durable persistence.

BENEFIT-TRIGGERED PERSISTENCE REMINDER
If session-only was chosen, re-offer persistence only when the current workflow has a concrete durability benefit: e.g. a large/multi-chat audit, WAITING_USER batch recovery, multi-account work, substantial newly captured state, planned continuation later/on another device, or a reload/recovery limitation. Explain the specific benefit in one sentence. Never interrupt trivial work, never remind more than once per runtime session, and when reliable reminder metadata exists enforce at least a 7-day cooldown. `not now` suppresses the runtime session; `don't ask again` suppresses future reminders until the user explicitly reopens persistence setup.
