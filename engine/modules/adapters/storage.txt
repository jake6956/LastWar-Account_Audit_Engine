load_class: capability_on_demand

SANITIZED: YES
ACCOUNT STATE INCLUDED: NO

CORE RULES
Cloud storage is optional but recommended. Use an isolated LWAI workspace. Choose storage by verified capability, not brand assumptions. The logical LWAI schema is invariant across providers even when physical file types differ. Local account state must survive upstream engine upgrades and provider migration.

MULTI-ACCOUNT PHYSICAL MODEL
A persistent multi-account deployment uses one workspace-level Account Registry plus one isolated account database/logical namespace per immutable account_id when practical. Never collapse multiple accounts into one ambiguous mutable table set merely because a provider has weak structure semantics. Human display names are aliases, not storage identity. Shared engine/Gold Assets are read-only with respect to account facts.

LOGICAL MODEL
Workspace Registry fields include account_id, nickname, optional/private game_uid and uid_suffix, screenname, alliance, server, status/active flags, identity-confirmed/updated dates and provider-local database reference. Workspace metadata includes active_account_id, schema version, discovery policy, adapter and privacy policy. Each account namespace contains Account Identity plus Dashboard; Heroes; Gear Pool; Presets; Tech; Research Queue; Resources; Drone; Decorations; Profession; Overlord/Season Systems; Battle Log; Change Log; Corrections; Mechanics observations; Hot Cache; State Health; Staleness state; Snapshots; preferences and assets.

GOOGLE DRIVE
When native Sheets read/write exists, use a workspace registry Sheet plus one isolated canonical account database Sheet per account when practical. Existing legacy single-account Sheets may be registered in place without rewriting their historical domain data. Use Docs for contracts/readmes/manifests and account-specific folders/namespaces for private assets.

GENERIC WRITABLE FILE STORAGE
Without true structured-table semantics, use a versioned workspace registry file plus separate account directories/files keyed by immutable account_id, using JSON/CSV plus Markdown/TXT. Preserve unique IDs, timestamps, source/confidence, Change Log, Corrections and engine version.

READ-ONLY / WEAKLY WRITABLE CLOUD
Reference-only providers cannot be canonical writable state. If safe independent per-account writes cannot be guaranteed, do not advertise full multi-account persistence; use chat/private snapshots or recommend a stronger writable provider.

PROVIDER / SINGLE-ACCOUNT MIGRATION
Snapshot canonical state and engine metadata first. For a legacy single-account deployment, generate account_id, create/register the Workspace Registry, register the existing database in place, add Account Identity if supported, set active_account_id and preserve all existing domain records. For provider migration, export provider-neutral state and validate account registry count, account IDs, latest values, Corrections and Change Log continuity. Do not destroy the old store until reconciliation passes.

PROVIDER HEALTH
Verify expected write scope, structured operations where claimed, all writes stay inside LWAI workspace, account namespaces remain isolated, timestamps/source/confidence survive, reload resolves active_account_id, a switch cannot write to the prior account, and provider disconnect degrades gracefully rather than corrupting state.

PRIVACY
Identity fields including optional game UID are provider-local private data. Do not copy them into shared GitHub Production, public Gold Assets or another deployment. Prefer masked UID suffixes in account-selection displays.

UPSTREAM RELATIONSHIP
Provider adapters are ENGINE. Workspace Registry, active_account_id, identities, credentials, provider-local paths, user files and mutable account state are LOCAL STATE and must never be overwritten by engine refresh.
