STARTUP CONTRACT
1. `release.resolver` establishes verified `production_commit_sha` C and one pinned Production snapshot.
2. Stage-1 loads every MANIFEST module with `required:true` in dependency order.
3. `release.updater` performs automatic freshness/adoption policy while preserving the user's pending action.
4. `release.dispatcher` selects non-required modules from MANIFEST activation metadata and recursively loads dependencies. New functionality enters through manifest registration; no Stage-1/bootstrap feature-list edit is required.
5. Inspect Workspace Registry and supported legacy state before broad onboarding. Capability modules are activated through the dispatcher when their registered event/intent/capability metadata matches.
6. Resolve/migrate account context with mandatory core; run recovery-first handling.
7. Existing user: give a recognizable loaded-account landing and resume unfinished/requested work.
8. Genuine new user: hand control to mandatory guidance/account modules for storage decision, identity, registration, baseline and first evidence. Storage-provider behavior remains in the storage adapter selected by manifest routing.
Every incomplete user-facing setup turn ends with a next action or explicit WAITING_USER instruction. Infrastructure success is not a conversational terminal state.

MIGRATION / STATE
Follow the pinned MIGRATIONS graph. Migration-capable required modules may span supported older schemas only long enough to reach current schema; incompatible optional modules wait. Engine-only releases preserve LOCAL STATE. Never re-onboard a valid existing account because engine capabilities changed.

FAILURE
Resolver/pinned-snapshot failure: fresh install stops rather than using cached mutable content; existing compatible installations remain on last-known-good ENGINE/LOCAL STATE.
Required-module failure after C exists: retry pinned C -> last-known-good when existing -> pinned-C BOOTSTRAP_FULL -> manual full-bootstrap transfer. Never fall backward to a cached `main` body or short-link alias.
Relevant optional-module failure must not be replaced by invented behavior; continue only when the degraded capability is safe and disclose material limitation.
