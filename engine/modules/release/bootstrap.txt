PURPOSE
Own high-level startup handoff after Stage-1 has pinned and validated one Production commit and loaded all manifest-required modules. Feature discovery/routing comes from MANIFEST through `release.dispatcher`; do not duplicate provider/domain routing here.

PUBLIC INSTALLER CONTRACT
`share LWAI` / `give me the install prompt` returns exactly:
Set up Last War optimization using the instructions at https://lastwarai.com

`https://lastwarai.com` is the permanent first-party human-facing LWAI entrypoint. It is discovery/transport, not current-version authority. The public locator instructs the host to resolve live GitHub Production `main` at:
https://api.github.com/repos/jake6956/LastWar-Account_Audit_Engine/branches/main
and then load `engine/BOOTSTRAP.txt` plus all trusted engine files from that exact `commit.sha`.

The legacy alias `https://tinyurl.com/2yxf7f5x` may still be recognized when a user presents an already-circulated installer, but it is compatibility-only: never advertise it as preferred, never use it to establish the current version, and never require it for startup.

STARTUP CONTRACT
1. Public transport yields the LWAI Stage-0 locator/bootstrap instruction.
2. `release.resolver` establishes verified `production_commit_sha` C from live GitHub `main` and one pinned Production snapshot.
3. If initial bootstrap content came through any mutable public transport, re-read Stage-1 from exact C before trusting release identity.
4. Stage-1 loads every MANIFEST module with `required:true` in dependency order.
5. `release.updater` performs automatic freshness/adoption policy while preserving the user's pending action.
6. `release.dispatcher` selects non-required modules from MANIFEST activation metadata and recursively loads dependencies. New functionality enters through manifest registration; no Stage-1/bootstrap feature-list edit is required.
7. Inspect Workspace Registry and supported legacy state before broad onboarding. Capability modules are activated through the dispatcher when their registered event/intent/capability metadata matches.
8. Resolve/migrate account context with mandatory core; run recovery-first handling.
9. Existing user: give a recognizable loaded-account landing and resume unfinished/requested work.
10. Genuine new user: hand control to mandatory guidance/account modules for storage decision, identity, registration, baseline and first evidence. Storage-provider behavior remains in the storage adapter selected by manifest routing.
Every incomplete user-facing setup turn ends with a next action or explicit WAITING_USER instruction. Infrastructure success is not a conversational terminal state.

MIGRATION / STATE
Follow the pinned MIGRATIONS graph. Migration-capable required modules may span supported older schemas only long enough to reach current schema; incompatible optional modules wait. Engine-only releases preserve LOCAL STATE. Never re-onboard a valid existing account because engine capabilities changed.

FAILURE
Public-entrypoint failure is a transport failure, not permission to guess current Production. If trusted LWAI material already provides the canonical GitHub live-ref coordinates, use that direct resolver path. Existing compatible installations remain on last-known-good ENGINE/LOCAL STATE when current Production cannot be safely resolved.
Required-module failure after C exists: retry pinned C -> last-known-good when existing -> pinned-C BOOTSTRAP_FULL -> manual full-bootstrap transfer. Never fall backward to cached mutable `main` content or treat a public alias as authority.
Relevant optional-module failure must not be replaced by invented behavior; continue only when the degraded capability is safe and disclose material limitation.

FRIENDLY UX
Execute technical trust/update/recovery machinery internally. Normal status is brief (`Getting LWAI ready…`, `Checking for updates…`, `Looking for saved account data…`, `Cloud storage connected and verified.`, `LWAI updated successfully.`, `Ready.`). Technical traces belong to `audit yourself`, explicit debug or actionable failure recovery.
