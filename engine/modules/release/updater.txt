LWAI MODULE — AUTOMATIC ENGINE UPDATER
module_id: release.updater
module_version: 2026-08-30.24.1
load_class: mandatory_core
state_scope: shared_engine+workspace_engine_metadata
SANITIZED: YES
ACCOUNT STATE INCLUDED: NO

PURPOSE
Keep a running LWAI deployment on the newest verified Production engine without reinstalling, while preserving LOCAL STATE and never trusting stale mutable-path content.

AUTHORITY / RESOLUTION
`release.resolver` is the only Production freshness authority. Every update transaction first resolves the live GitHub `main` head to immutable `production_commit_sha` C, then reads candidate LATEST/MANIFEST/MIGRATIONS/BOOTSTRAP/modules only at C.
Never decide latest from search results, indexed GitHub pages, README snapshots, URL aliases, cached raw `main` files or model memory. Never auto-load RC/Prod-Dev. Never downgrade.

UPDATE POLICY
Default consumer update_policy is AUTOMATIC when a live-ref capability exists. Check:
1. every runtime/session startup before ordinary account/domain work;
2. `reload LWAI` / `reload yourself`;
3. schema-sensitive migration/recovery boundaries;
4. consequential work in a long-lived runtime when >=6h since the last successful live check.
Do not check every trivial message. `refresh engine` bypasses TTL and forces the same transaction.

WORKSPACE ENGINE METADATA
Durable writable workspaces may store compact shared-engine metadata:
- installed_engine_version
- installed_production_commit_sha
- last_successful_update_check
- last_successful_engine_update
- last_known_good_engine_version
- last_known_good_production_commit_sha
- last_resolved_production_commit_sha
- resolver_method / resolver_health
- update_policy / update_health
- optional compact last_update_error_summary
These values are operational metadata, not account evidence or routing state. Session-only equivalents are ephemeral.

AUTOMATIC UPDATE TRANSACTION
At a trigger:
1. Preserve current ENGINE identity and last-known-good references.
2. Call `release.resolver`; obtain verified live C. If live resolution fails, keep last-known-good and follow FAILURE behavior.
3. Fetch/validate `releases/LATEST.json` at C. If its Production engine_version is not newer than installed, record a successful check (including C) and resume the original user action silently.
4. If newer, fetch at the SAME C: MANIFEST, MIGRATIONS, BOOTSTRAP and changed required components. Require Production channel, sanitization/privacy flags, API/workspace compatibility, declared migration chain and available integrity.
5. Fetch only changed mandatory components plus task-relevant modules. Never mix commits.
6. Apply only declared validated migrations. Engine-only releases preserve LOCAL STATE. Schema transitions preserve registry, immutable account_id, active_account_id, canonical account facts/history, Corrections, evidence metadata, recovery/session state and provider references.
7. Health-check the pinned candidate graph before activation.
8. Atomically adopt the verified engine at C, update compact metadata, then resume the user's original requested action.

FRIENDLY UPDATE UX
No-op is silent. When useful say `Checking for updates…`; after a real successful update use at most `LWAI updated successfully.` and immediately continue the original task. Keep URLs, commit SHAs, manifests, hashes, migration traces and module lists inside `audit yourself`, debug, or actionable recovery detail.

FAILURE / ROLLBACK
Live-ref failure, identity/privacy/API/schema/migration/integrity/retrieval failure, or failed health check never partially activates a candidate and never alters LOCAL STATE.
Existing compatible deployments retain last-known-good ENGINE and may continue safe requested work; report degraded freshness only when materially relevant. If compatibility is insufficient for the requested operation, fail closed.
Fresh installation is governed by Stage-0/BOOTSTRAP: unresolved live Production stops rather than loading a cached older engine.

MANUAL BREAK-GLASS
`refresh engine` is a permanent backwards-compatible public command. It forces `release.resolver` + the same pinned update transaction while preserving LOCAL STATE. `check for LWAI updates` is an alias.

NO BACKGROUND CLAIM
Automatic means interaction-triggered preflight. Do not imply updates occur while the conversation is dormant unless the user separately opts into a genuinely available scheduler.

PRIVACY
Update resolution/retrieval uses public sanitized engine metadata only. Never publish or move identity, UID, screenshots, balances, Corrections, battles, account state, session/recovery rows or provider-local references into GitHub.
